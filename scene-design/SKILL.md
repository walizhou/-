# 场景设计 V0.1

将初步想法转化为有明确空间关系、视觉重点和光影逻辑的场景方案及可直接使用的提示词。默认中文，按任务规模精简输出。不把仙侠、古风或任何既有案例当成通用默认。

## 入口与边界

先根据用户意图选择路径，表达明确时直接执行，不要求用户填写表格。

| 路径 | 决定因素 | 保留与变化 |
|---|---|---|
| A 需求设计 | 需求决定场景 | 依用途设计布局与风格 |
| B 风格迁移 | 图片决定视觉规律，需求决定新场景 | 保留风格关系，重新设计功能、物件和布局 |
| 原图复现 | 图片决定原画面 | 优先保留布局、主体、比例和机位；说明不可见区域的不确定性 |
| 定向修改 | 图片为基底，用户决定变化 | 明确修改项和锁定项，避免扩大修改范围 |

“照着这张图做”若无法判定是迁移还是复现，先问一个关键问题。需要图片但无法读取时，请用户补充原图；不得假装看过。可以先提供文字需求方案，并明确尚未完成图像分析。

## 共用流程

1. 提取用途、场景类型、时代或世界观、必需元素、空间关系、情绪、画幅和禁用项；区分已知条件、合理假设、待确认项。仅当缺失会改变核心方向时提问，其余作最少假设并标明。冲突条件先指出并解决。
2. 按下述 A 或 B 流程建立设计。原图复现和修改沿用上表的保留规则，不转成自由重设计。
3. 先解决空间与视觉问题，再写提示词。确定主体、相对位置、通道或留白、遮挡关系、观看位置；需要时组织前中后景，不强加复杂层次。光源方向应与窗户、投影、受光面和材质透光相符。
4. 输出方案与提示词，按质量清单检查并修正明显矛盾。提示词不能代替实际生成验证。

## A：需求驱动

- 风格明确：遵循用户设定，不额外混入无关风格。
- 风格未定：根据用途和情绪提出 2–3 个有实质区别的简短方向，说明各自的空间、材质与光色差异，并推荐一个。用户要求直接完成时，以推荐方向完成首稿，标注这是建议，不强制等待确认。
- 设计顺序：功能与空间 → 主体及配角 → 美术方向 → 材质与色彩 → 光源 → 机位与构图。不要用“电影感、8K”等词掩盖布局缺失。

## B：参考图驱动

先实际查看图片。分别记录可观察事实与推测；不凭单张图断言精确尺寸、焦距、材质成分、历史年代或被遮挡结构。

按六个维度简要分析：空间层次、美术表现、主辅及点缀色、光源方向与软硬、材质外观、景别机位与透视。随后分成两组：

- 内容：床、窗、山、桌等具体对象及其位置。
- 可迁移规律：如深色木器与浅色半透织物的明度对比、低饱和青绿环境与暖色侧光、局部前景遮挡形成纵深。

提取 3–5 条最有识别度的规律，为每条写明可见依据及新场景的落地方式。不得只堆风格标签，也不得机械复制原图家具。书房应具备阅读与收纳功能，而不是把客房的床搬过去。多图冲突时区分各图用途，明确主参考或提出取舍。

原图复现：描述可见结构并优先匹配；不承诺像素级一致。定向修改：列出“修改／保留”，提示词只围绕指定差异组织；若实际生成或编辑被请求，使用可用图像工具并遵循其工作流。只有设计或提示词请求时，不自动生成图片。没有工具时交付方案并说明能力限制，不声称已完成编辑。

## 输出格式

默认交付以下四项，可按用户要求缩短；只要提示词时直接给提示词，必要假设一句说明。

1. **任务与设定**：路径、目标、硬约束及影响结果的假设。风格未定时附简短方向建议。
2. **设计方案**：布局与主体、风格材质、光影色彩、机位构图。B 额外附“参考依据 → 风格规律 → 新场景应用”的简表；复现或编辑附保留／变化项。
3. **完整提示词**：场景与用途 → 空间和物件关系 → 风格材质 → 光色 → 构图画幅 → 限制。内容自包含，不依赖“同上”；用户未要求时不强加英文版本。避免矛盾形容词、无意义质量词和未经确认的平台参数。负面提示仅在适用时单列，普通限制可直接写入正文。
4. **检查与下一步**：说明本次完成的是方案检查还是实际图像验证，给出最值得验证的 1–3 点；存在关键不确定性时说明。

## 验证与迭代

交付前检查：硬约束是否满足；空间与机位是否相容；主体是否突出；光影和材质是否协调；提示词与方案是否一致；B 是否迁移规律且适配新功能；修改是否越界。发现问题先修正。

拿到生成图或反馈后，按空间、主体、风格、光色、材质、构图定位具体偏差，优先调整 1–2 个关键因素，保留已认可部分。没有生成图时只做文本检查，不宣称效果已验证。解决当前偏差后停止该轮；用户可继续反馈，不无限重试。

仅将有实际证据的经验记入 [EXPERIENCE_LOG.md](EXPERIENCE_LOG.md)，记录失败同样有价值。单次结果标为待复验；案例偏好不升级为全局规则。用户反馈反复证明规则有效后，再作小范围修改并更新 [CHANGELOG.md](CHANGELOG.md)。不为每次使用自动改写技能；记录避免保存无关个人信息。

需要回归检查时使用 [TEST_CASES.md](TEST_CASES.md)。V0.1 不承担施工图、精确三维建模、资产库管理、视频运镜或跨机位绝对一致性，不保证任意平台严格执行提示词。
